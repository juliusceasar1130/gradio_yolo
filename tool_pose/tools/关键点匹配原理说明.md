# 关键点查找匹配原理说明

## 📋 工作原理

### 1. 整体流程

```
Labelme JSON文件
    ↓
找到边界框 (rectangle) - label="tool1"
    ↓
根据label查找class_mapping配置 - 获取keypoints列表 ['1', '2', '3', ...]
    ↓
对每个keypoint名称：
    - 构建完整标签：f"{label}_{kpt_name}" → "tool1_1"
    ↓
遍历所有shapes，查找：
    - shape_type == 'point' 
    - label == "tool1_1"
    ↓
找到 → 提取坐标并归一化
未找到 → 使用默认值 (0, 0, visibility=0)
```

### 2. 代码逻辑详解

#### 步骤1：处理边界框
```python
# 第56行：遍历所有shapes，只处理rectangle类型
for shape in data['shapes']:
    if shape['shape_type'] == 'rectangle':
        label = shape.get('label', '')  # 获取边界框的label，如"tool1"
```

#### 步骤2：获取类别配置
```python
# 第78-84行：根据label查找配置
class_info = class_mapping[label]  # 获取该类的配置
expected_keypoints = class_info['keypoints']  # 获取关键点名称列表
# 例如：['1', '2', '3', '4', '5', '6', '7']
```

#### 步骤3：构建关键点标签名
```python
# 第88-90行：为每个关键点构建完整标签名
for kpt_name in expected_keypoints:  # kpt_name = '1', '2', '3'...
    full_kpt_name = f"{label}_{kpt_name}"  # "tool1" + "_" + "1" = "tool1_1"
```

#### 步骤4：查找匹配的关键点
```python
# 第94-98行：在所有shapes中查找匹配的点
for kpt_shape in data['shapes']:
    if (kpt_shape['shape_type'] == 'point' and      # 必须是point类型
        kpt_shape.get('label', '') == full_kpt_name): # label必须完全匹配
        found_kpt = kpt_shape  # 找到匹配的关键点
        break
```

#### 步骤5：提取坐标
```python
# 第101-104行：如果找到，提取坐标并归一化
if found_kpt:
    kpt_x, kpt_y = found_kpt['points'][0]  # 关键点的像素坐标
    norm_x = kpt_x / image_width   # 归一化到0-1
    norm_y = kpt_y / image_height  # 归一化到0-1
```

```json
      "shape_type": "point"
    }

  ]

```

### 程序期望的匹配：
```python
# 如果配置文件中：
class_mapping = {
    'tool1': {
        'keypoints': ['1', '2', '3', '4', '5', '6', '7']
    }
}

# 程序会查找：
# "tool1_1"  ← 但您的标注是 "t1_1" ❌ 不匹配
# "tool1_2"  ← 但您的标注是 "t1_2" ❌ 不匹配
# "tool1_3"  ← 但您的标注是 "t1_3" ❌ 不匹配
```

---

## ❌ 为什么匹配失败？

**原因：**
1. 程序构建的标签：`"tool1_1"`（类别名_数字）
2. 您标注的标签：`"t1_1"`（简化格式，类别简化为"t1"）

**结果：** 找不到匹配，所有关键点都用默认值 `(0, 0, 0)` 填充

---

## ✅ 解决方案

### 方案1：修改Labelme标注（推荐）
在Labelme中将关键点标签改为完整格式：
- 改为：`tool1_1`, `tool1_2`, `tool1_3`, ...
- 配置文件保持不变：`keypoints: ['1', '2', '3', ...]`

### 方案2：修改配置文件
保持Labelme标注不变，修改配置文件：
```yaml
class_mapping:
  tool1:
    class_id: 0
    keypoints:
      - t1_1    # 使用完整标签名
      - t1_2
      - t1_3
      - t1_4
      - t1_5
      - t1_6
      - t1_7
```

但这样需要在配置文件中写完整的标签名，不够优雅。

### 方案3：增强程序（需要修改代码）
修改程序支持灵活的匹配规则，可以同时支持：
- 标准格式：`tool1_1`（类别名_关键点名）
- 简化格式：`t1_1`（如果配置的keypoints是数字）

## 🎯 关键点说明

1. **匹配是精确匹配**：必须完全相等，不支持模糊匹配
2. **区分大小写**：`"tool1_1"` ≠ `"Tool1_1"`
3. **必须同时满足两个条件**：
   - `shape_type == 'point'`
   - `label == full_kpt_name`
4. **查找顺序**：按配置文件中的keypoints顺序查找，按JSON中的顺序匹配

---

## 💡 建议

**最佳实践：**
1. 使用统一的命名规范：`类别名_关键点名`
2. 在配置文件中的keypoints只需要写关键点的基础名称，程序会自动拼接类别名
3. 保持Labelme标注和配置文件的一致性
